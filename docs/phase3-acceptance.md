# 第三阶段自动协作验收

验证日期：2026-10-28；系统版本：0.3.0；实施端：官方独立 CodeBuddy Code 2.177.1，使用用户完成的正规登录。

## 真实最小交付

使用独立测试数据库和项目目录，启用任务授权与总调度后，系统自动启动 Codex 规划，再启动 CodeBuddy Code 实施。两端均通过绑定本轮的 MCP 领取、心跳与交接，进程正常退出（退出码 0）。最终任务为 review，owner 为空，未自动验收。

实施端通过 Write 创建 proof.txt，再通过 Read 读回文本并提交真实证据。测试宿主随后独立读取原始字节，确认精确内容 cross-app-auto-ok，共 17 字节，无 BOM、无换行。SHA-256：438cd276360499076f4542d452552c12ebf760abff6f6df9b97345f4f0200b1a。

原生 Read 的文本输出不用于冒充字节级测量；实施端未测量的字节条件由测试宿主独立核验。该分工仅用于此次隔离测试，业务任务仍需按各自验收标准检查。

## 真实阻塞转交

另一次隔离运行中，实施端写入成功后申请未预授权的字节检查命令，被默认权限模式拒绝。实施端停止并 report_blocked，系统自动启动 Codex 诊断，最终转 needs_human；三次执行均完成交接并退出。没有通过关闭审批或改用其他命令来绕过拒绝。

## 回归与范围

- 57 项自动测试通过：角色和租约、暂停、超时、重启恢复、重复派发、进程退出、登录失败、HTTP/MCP 边界及启动器权限。
- 使用本机安装包的实际参数解析器与路径匹配函数，10 项目录匹配检查通过：中文和空格目录内匹配，相邻项目、父目录及外部路径不匹配。
- Codex 保留 workspace-write 和自动审批审查；CodeBuddy 保留 default，仅为当前项目文件读写及本系统交接工具预授权。

以上证明了最小文件交付和真实权限阻塞后的自动转交。未将复杂项目、任意 shell 命令、所有故障类型或既有桌面聊天控制记为已验证。路径匹配不是操作系统沙箱，不替代客户端对链接路径及既有用户权限的检查。额外命令权限不足时仍会停止，成果仍需人工验收。

使用步骤与恢复方法见 [调度指南](scheduling.md)。原始模型日志、隔离数据库及本机路径证据只保留在被忽略的本地 .qa 目录。
